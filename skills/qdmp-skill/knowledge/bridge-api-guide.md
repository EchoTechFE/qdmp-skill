# 千岛小程序 Bridge 工作流

先执行 [事实查询流程](./api-discovery.md)，选择 Bridge provider。接口名称、同步/回调/Promise 形式、参数、返回、事件和平台支持从 MCP 获取；不复制 API 目录或通用调用签名。

## 授权与登录

保留宿主登录 → 获取临时凭据 → 服务端交换 → 业务请求的分层流程，交换能力须单独确认。用户主动进入受保护功能时先查询授权状态，再按需申请，分别处理确认、拒绝、取消和能力不支持。首次操作引导与业务失败后的单次恢复分开；不能将原生调用成功等同于业务已授权。

## 千岛生态与内容回流

区分查询入岛状态与加入操作。发帖保留预填 → 打开发布页 → 用户编辑确认 → 处理终态的流程；媒体、标签和业务透传的编码由 MCP 字段说明决定。取消想要或删除标记使用真实记录身份；不能以同名 HTTP 接口替换。IM 订阅使用业务提供的模板，逐模板处理结果。分享与图片悬浮窗分别核实支持和生命周期。

## 网络、存储与路由

下载、上传和 Socket 保留任务对象、进度、完成/失败与取消的区分；派发完成不能冒充传输成功。同步返回直接使用，异步与回调按契约衔接；不能套用统一 Promise 包装。路由参数由应用提供，URL 值使用 encodeURIComponent，保留原页面栈逻辑。

## 界面、媒体与设备

导航栏返回首页和普通返回动作分别处理。图片、视频、相机、音频按需求查询，普通音频见 [inner-audio.md](./inner-audio.md)。陀螺仪等传感器保留先监听再启动、页面隐藏/卸载停止并解绑的顺序；解绑使用原监听函数。BLE 见 [bluetooth.md](./bluetooth.md)。同步系统信息不包装成异步调用。截图隐私与屏幕方向属于编译期页面配置，见 development-guide。

## 位置、文件、节点与画布

先确认顶层工厂/获取入口，再确认返回对象的成员方法。位置监听解绑与底层定位停止分别处理；只清理当前业务注册的回调。文件路径来自实际返回值。节点查询和画布保留准备、执行、读取结果和页面销毁的顺序。

## 验收

保留正常、拒绝、取消、能力缺失、同步异常、Promise 拒绝、事件完成、并发操作与资源清理场景。方法返回和实际事件分开记录；平台支持使用 MCP 摘要，跨端真实行为在目标 App 验证。契约缺少的终态、配套方法或成员不能用旧文档补齐。
