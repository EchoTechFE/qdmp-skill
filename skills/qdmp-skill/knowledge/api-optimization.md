# 业务 API 优化与兼容性

设计、修改、审查或排查业务 API 时，先根据项目入口、依赖锁和实际运行配置确认服务语言、框架、数据库以及调用方。检查本次业务链路的明显风险，已有查询、分页和授权设计满足需求时直接复用。常规交付做功能回归即可，性能测量、压测和 profiling 不作为前置或验收项。

## 通用规则

- 新增可能增长的列表或搜索时，约定默认和最大页大小、稳定排序（并列时用唯一键）、下一页标识和结束条件。数据量大或持续滚动的列表优先考虑游标；已有页码、总数、排序和默认行为继续兼容。每页都检查用户权限和可见范围，游标不代替鉴权。新增分页会改变旧响应时，通过独立路由或显式参数分阶段接入。批处理也要限制条数。
- 在实际请求中把筛选、投影和页大小下推到数据层。只取首屏所需字段；用 ID 批查代替逐条查询，保持原列表顺序、权限和缺失项语义。索引对应实际筛选和排序，沿用项目迁移方式，避免为无关读路径改线上索引。
- 给数据库及下游请求设限、尽量传递请求取消。连接池和 HTTP 客户端按进程生命周期复用。按既有契约处理超时和失败；只有可安全重复的操作才按预算重试，写入和一次性授权码不得盲目重放。缓存只在业务允许短时陈旧时使用，按应用、用户、权限和查询隔离，明确失效和回退。
- 验证本次改动会影响的旧请求与新请求。分页至少检查空页、末页、相同排序值、重复触发及切换查询条件。路由、会话、数据归属和错误响应以既有契约为准。

## Node.js

- 保留已有 CommonJS 或 ESM、框架和包管理器；以实际 Node 版本及锁定的 HTTP/数据库客户端为准。请求热路径用异步 I/O，避免同步文件或压缩操作、无上限的 JSON 和数组处理。大输入限制体积或采用客户端已支持的流式路径，遵守流的背压及清理约定。 [Node.js 事件循环](https://nodejs.org/en/learn/asynchronous-work/dont-block-the-event-loop)
- 列表关联优先用当前 ORM/驱动的投影和批查询，避免对无上限集合做 `Promise.all`。确需并行的独立读操作限制并发。沿用框架和客户端的超时与取消；支持 `AbortSignal` 时传给实际接受它的请求，旧运行时沿用驱动的超时/中止能力。只让 `Promise.race` 提前返回不会取消底层 I/O。 [Node.js AbortSignal](https://nodejs.org/api/globals.html#class-abortsignal)
- 使用项目已有测试命令验证分页、依赖失败和关闭资源。正式部署另核对 [Node.js 发布契约](./backend-production.md#node-配置加载与运行契约)，业务优化本身不要求升级旧 Node 或迁移模块格式。

## Python

- 按真实入口确认同步服务（例如 WSGI）或异步服务（例如 ASGI），依赖版本以实际环境和项目锁定为准。同步 handler 继续用有超时的同步客户端。异步 handler 优先用已接入的异步客户端，不直接在事件循环做阻塞 I/O。必须调用同步库时用框架已有的有限线程机制，并给底层客户端独立设超时。取消等待不保证已经运行的线程停止。纯 CPU 长任务沿用项目已有的 worker/任务队列机制。
- 让 ORM/驱动在数据库中分页和投影，先排序和限制再物化结果。批量预取关联时限制数量，避免逐条加载。按框架约定管理请求级 session/事务及池化客户端，异常时回滚和释放。异步任务用有界并发并正确传播取消，按已安装版本选择 `wait_for` 或 `asyncio.timeout`（Python 3.11+），避免用新 API 迫使旧项目升级。 [Python asyncio 官方说明](https://docs.python.org/3.12/library/asyncio-task.html#timeouts)
- 运行项目既有的 `pytest`、`unittest` 或框架测试。Python 项目沿用已有部署路径。QDMP CLI 报 `backend_runtime_unsupported` 时按实际缺口报告，保留 Python 实现，前端工作按原范围继续。 [后端正式发布支持范围](./backend-production.md)
