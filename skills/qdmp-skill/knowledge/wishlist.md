# 心愿单工作流

心愿单 Folder 与单个商品想要、拥有、标记和帖子收藏分别处理。先按 [事实查询流程](./api-discovery.md) 确认心愿单的列表、详情、创建和条目修改能力；不能用“想要”搜索结果代替心愿单。若 MCP 未收录心愿单或授权能力，说明缺口，继续其他工作。

## 业务顺序

保留用户进入 → 查询授权 → 列表 → 详情 → 用户明确创建/修改 → 刷新实际结果的流程。默认值、数量是增量还是覆盖、移出条目的条件、心愿价单位和未设置语义，都从当前契约读取；不能用显示默认值回写用户数据。列表与条目各自维护分页状态，去重和结束条件依据契约。

写操作只由用户意图触发。请求发出后，即使超时、断网或解析失败也不自动重放；先读取实际结果，再让用户决定后续动作。权限申请与业务写入分开，不因重新登录或授权成功自动重复写入。

## 验收

保留空列表、多页、详情丢失、权限拒绝、数量覆盖/移出、心愿价未设置与明确值、重复点击、写入超时和回读失败场景。每项断言使用本次 MCP 契约确认的字段和语义；测试历史不作为当前 API 的授权或参数来源。
