# 普通音频工作流

先按 [事实查询流程](./api-discovery.md) 查询创建工厂、所属实例和本次所需成员；事件与属性也须由事实确认。成员未独立收录时可检查 owner 的完整声明，不能臆造独立 ID 或凭历史模板补全签名。

## 实例与音源管理

保留明确创建、播放/继续、暂停、停止、销毁五种操作。实例保存在普通变量或闭包，展示状态可响应式；方法保持所属实例的 this。创建不主动播放，未创建时提示先创建，暂停后沿用同一实例与音源，音源未变不重复设置。网络/本地音源使用真实值，不为播放自动下载。销毁失败保留原始错误和本地引用。

[调用模板](../assets/inner-audio.mjs) 保留 create/play/pause/stop/destroy 控制接口、并发保护和原始日志。调用方根据 MCP 契约生成 bindings，逐操作提供 `id` 与 `invoke`；播放另提供 `configureSource(owner, source)`，把契约声明的属性设置放在适配层。模板不内置原生名称、参数或属性。invoke 接收所属对象并保留其方法接收者；create 使用调用方闭包中的 SDK。没有已核实的适配层时不执行。

## 返回值与事件

分别记录 request、returned/resolved、threw/rejected 和 blocked；日志字段属于应用封装，不是 SDK 字段。保留原始同步值、undefined 和错误对象，记录函数异常不能改写原生结果。方法完成不等于声音已播放；事件名称、注册解绑和载荷按 MCP 契约生成。只解绑当前业务注册的监听，页面离开后按产品生命周期释放实例。

## 验证重点

- 创建不自动播放，未创建的控制操作不会隐式创建。
- 播放 → 暂停 → 播放沿用实例和音源；停止与暂停分别验收。
- 销毁后提示先创建，再次明确创建后才可播放；销毁失败不冒充成功。
- 调用结果与事件分开，保留同步异常、Promise 拒绝、属性配置失败和并发操作的真实记录。
- 真实发声、音源支持和跨端行为在目标千岛 App 验证，封装测试不作为平台支持结论。
