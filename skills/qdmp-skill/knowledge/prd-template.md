# PRD 模版说明

## 什么是好的 PRD

一份好的 PRD 应该让产品、开发、设计、测试都能从中找到自己需要的信息，而不需要反复追问。核心标准：

- **背景清晰**：为什么做这个，解决谁的什么问题
- **边界明确**：做什么、不做什么，都要说清楚
- **流程完整**：用户怎么一步步完成目标，异常情况怎么处理
- **状态可追踪**：每类数据有哪些状态，怎么流转
- **验收可测**：每个功能点都能写出测试用例

---

## PRD 模版

仅在缺少有效 PRD、用户确实需要建立入口时使用此结构；专题按业务域复用所需小节。已有文档优先按 [PRD 归档与迭代](./prd-lifecycle.md) 更新。占位符、没有依据的角色和未要求的指标不要写入成稿。实现细节已有对应文档时，引用其有效章节。

```markdown
# [项目名称] 产品需求文档

## 范围与角色

[说明产品目标、服务对象、明确纳入和排除的范围，以及角色的权限边界。]

[如有专题，链接并说明所属业务域。]

## [业务模块]

- 场景与入口：[在什么条件下，哪个角色可以执行哪些操作。]
- 流程与状态：[主要步骤、业务状态变化和结果。]
- 规则与异常：[验证、权限、可见性、限制值及错误后的处理。]
- 数据与依赖：[与需求直接相关的字段约束或关系，已有接口或数据字典则链接。]
- 验收：[可复现的正常、边界与异常结果。]

## 待确认事项

[仍缺明确依据的差异、影响及来源。无待确认问题可省略。]
```
