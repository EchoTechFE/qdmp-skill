# 千岛开放平台 HTTP API 工作流

实现业务调用前执行 [事实查询流程](./api-discovery.md)，选择 OpenAPI provider。地址、方法、请求头、字段、响应、错误码、权限、配额均读取本次 MCP 事实。服务端凭据只在后端使用；不把密钥下发前端。

## 认证与请求封装

保留获取凭据、缓存、按有效期提前刷新、并发刷新合并和失效后重新登录的流程。有效期单位、刷新条件、凭据字段及业务失败含义从契约确认；刷新失败时保留真实错误，只有仍有效且契约允许才沿用旧凭据。请求封装使用确认后的调用适配层，不复制认证地址或错误码表。认证交换若未被 MCP 收录，明确缺口，不能生成猜测的代理。

## Library：SPU / Tag / Island

先区分资料条目、标签和岛屿，再分别确认详情、搜索、关注、加入状态和已加入列表的能力。搜索条件、分页和 ID 类型逐接口核实；只展示真实查询结果，不用标签或岛屿 ID 代替条目 ID。加入状态查询与发起加入分别处理。

## Lifestyle：标记、想要与心愿单

标记记录、单个商品想要和心愿单是不同实体。列表/详情返回的记录身份用于后续操作，不把条目身份当作记录身份。字段、评分、批量行为、删除和权限分别核实。心愿单流程见 [wishlist.md](./wishlist.md)。

## Lifestyle：帖子、评论与回复

区分帖子发布、查询、本人列表、评论、回复和互动。逐项核实分页模式，不能让评论列表与回复列表共用未经确认的分页参数；ID 按契约保留精度。发布页打开、用户确认和发布成功分开处理；搜索不额外承诺契约未声明的过滤能力。写操作失败不自动重放。

## OSS 图片与视频上传流程

保留选择媒体 → 必要压缩/转换 → 查询容量 → 申请凭据 → 实际传输 → 核实审核/发布结果的分层流程；每个阶段必须有 MCP 契约。区分平台 OpenAPI、应用自建 relay 与对象存储请求。凭据中声明的方法、编码、表单/请求头及终态决定实现，不在不同版本的上传协议间回退。实际传输成功不等于审核发布成功。未收录视频、relay 或结果查询时报告缺口。

## OCR 与合作游戏价格

OCR 保留选图、格式/大小检查、转换、后端代理及结果展示；具体数据格式由事实决定。合作游戏价格先核对能力范围和用户/应用权限，不扩展为任意条目的价格查询，也不以同名 Bridge 替换 HTTP 接口。

## 错误与排查

记录实际 HTTP 状态、业务错误和可用的请求标识；按 MCP 事实区分应用权限、用户授权、凭据无效/过期、限流、配额和业务失败。不存在/方法不支持的路由停止轮询；权限和 WAF 问题不通过重复请求修复。用户授权恢复只在明确支持时执行一次，写请求失败不能因重新授权而盲目重放。

## 验收

保留已有正常、空结果、分页结束、权限拒绝、登录失效、限流、失败不重放和媒体发布状态用例。请求使用真实业务输入；测试夹具只模拟行为，不作为契约来源。调用清单与权限申请按 [openapi-permission-flow.md](./openapi-permission-flow.md) 执行。
