# 千岛小程序 Skill 使用指南

## 概述

千岛小程序 Skill 支持在 Claude Code、Codex 和 Qoder 中创建、开发和部署千岛小程序。

## 前置条件

1. 注册 [千岛开放平台](https://open.qiandao.com) 账号，创建小程序获取 `appId`；包含后端时再安全填写 `appSecret`
2. 安装 [Node.js](https://nodejs.org)，qdmp-cli 支持 `^22.12.0 || ^24.11.0 || >=26.0.0`
3. 选择一个支持的宿主，并按下文安装 Skill

---

## 一、环境配置

### 1. 安装开发工具

```bash
# 安装 pnpm
npm install -g pnpm

# 安装 qdmp-cli
npm install -g qdmp-cli

# 验证安装
qdmp-cli --version
pnpm --version
```

### 2. 添加 MCP 服务

以下是 Claude Code 的配置示例。使用其他宿主时，按该宿主的方式添加相同的 MCP 服务。

```bash
claude mcp add --transport http qdmp-gitlab https://openapi.qiandao.com/gitlab/mcp
claude mcp add --transport http qdmp-aliyun https://openapi.qiandao.com/aliyun/mcp
```

### 3. 安装 Skill

按仓库 README 中对应宿主的安装步骤操作。[安装说明](https://github.com/EchoTechFE/qdmp-skill#readme)

---

## 二、快速开始

在已安装 Skill 的宿主中调用千岛小程序开发助手，再描述要执行的操作。

### 创建项目

```
创建一个千岛小程序项目，项目名叫 myShop
```

新项目执行 `qdmp-cli create myShop`。需要填写应用身份或凭据时，按[对话配置指引](../knowledge/backend-production.md#凭据引导与自动写入)处理。

已有项目的迁移步骤见[旧项目迁移](../knowledge/project-workflows.md#旧项目强制迁移)。

项目结构：

```
myShop/
├── frontend/
│   ├── src/
│   │   ├── pages/        # 页面
│   │   ├── components/   # 组件
│   │   ├── composables/  # 组合式函数
│   │   └── utils/        # 工具函数
│   ├── package.json
│   └── qdmp.json         # 小程序配置（appId、loader 等非敏感配置）
├── backend/              # CLI 稳定 Go 生产模板，监听 :8080
└── qdmp-config.json      # 权威主配置（身份、runtime、MongoDB、后端variables；敏感，需忽略提交）
```

按[对话凭据引导](../knowledge/backend-production.md#凭据引导与自动写入)提供本次所需信息，由 Agent 写入受保护的根配置。前端只使用公开信息。

### 开发调试

**全量调试（推荐）**：

```
部署测试环境
```

Agent 先处理需要迁移的旧项目，再按本次操作范围启动服务。全栈联调先验证本地后端，再沿用项目配置运行项目的前端 EMP 开发脚本。默认模板从公开 AppID 推导正式后端域名，登录示例需要已部署的正式后端。已有项目按实际代理配置联调。直接运行 `pnpm dev` 时，先在项目根目录执行 `qdmp-cli config sync --json` 导出公开字段，再进入 `frontend/`。

Agent 会报告实际启动的进程、构建结果或监听地址。网页预览只在明确需要时启动。

**单独调试**：

```
部署后端测试环境    # 仅启动后端
部署前端测试环境    # 仅启动前端开发命令
```

**真机调试**：

```bash
qdmp-cli debug
# 使用千岛 App 扫码，CLI 进程保留以接收设备日志
```

### 发布上线

Agent 先完成旧项目识别与强制迁移：纯前端需要根主配置和 `frontend/`，只执行前端步骤，无需 AppSecret、Go 或数据库；全栈先后端再前端。小程序不存在纯后端项目；只有后端而无前端时报告结构不完整，有 `backend/` 但实现或配置缺失时报告待完善，不能降级为纯前端。

```
部署上线
```

全栈发布先完成后端测试和配置，再通过 CLI 部署并验收后端。后端通过验收后再上传前端。具体步骤见[后端发布与验收](../knowledge/backend-production.md)。

前端 `upload` 成功只表示上传版本。正式上线还需将真实版本设为体验版并提审；当前 CLI 支持 `qdmp-cli review --version <实际版本号> --auto-publish --json`，由平台在审核通过后自动发布。提审成功不代表已上线，最终状态以平台结果为准。发布规则、可选 diff 审查和验收由 Skill 维护，Agent 编排；CLI 执行，MCP/API 服务由平台提供。

修复或开发完成后，Agent 在本地检查通过并报告结果后主动询问是否继续真机测试、是否部署涉及服务。用户已经明确要求部署（包括“修改后部署”）时，直接构建当前工作区最新代码，自动生成版本描述、选择下一未占用 patch，并连续执行部署和验收，不再要求用户选择或再次确认版本。只有缺配置、构建失败、目标不明确，或可选审查发现异常差异时才报告具体阻塞。

## 三、详细功能

### 项目创建

**触发方式：**
- "创建千岛小程序"
- "新建小程序项目"
- "用 qdmp-cli 创建项目"

**执行内容：**
1. 列出可用模板
2. 询问项目名称
3. 创建项目目录
4. 安装项目依赖

### 开发调试

**触发方式：**
- "启动开发服务器"
- "运行小程序"
- "开发模式"

**执行内容：**
1. 检查项目目录
2. 确认依赖已安装
3. 启动开发服务器
4. 提供真机调试说明

### 打包部署

**触发方式：**
- "部署小程序"
- "上传小程序"
- "发布小程序"

**执行内容：**
1. 执行打包构建
2. 检查登录状态
3. 需要登录时，在 Agent 对话中展示浏览器链接和二维码图片，等待用户完成登录
4. 自动总结本次改动作为版本描述，并上传到开放平台

### 版本管理

**触发方式：**
- "查看版本历史"
- "回滚到上一个版本"
- "查看部署状态"

### 日志排查

**触发方式：**
- "查看服务日志"
- "查看启动日志"
- "排查报错"

### 数据建模

**触发方式：**
- "数据建模"
- "设计数据结构"

## 四、常见问题

### qdmp-cli 命令未找到

```bash
npm install -g qdmp-cli
```

如果仍然找不到，检查 npm 全局路径是否在 PATH 中：
```bash
npm config get prefix
# 确保 {prefix}/bin 在 PATH 中
```

### 依赖安装失败

先运行 `node --version`，核对[前置条件](#前置条件)中的 CLI 运行时范围。Node 20 不再受支持；保留旧纯前端项目源码，不代表旧 Node 仍可运行新版 CLI。运行时不兼容时使用已选择的受支持 Node 环境，不自动更换用户全局 Node，也不通过跳过安装脚本或编译检查绕过错误。

确认网络正常，可尝试：
```bash
pnpm install --registry https://registry.npmmirror.com
```

### 登录失败

1. 检查网络连接
2. 在支持输入的前台交互终端中执行目标 `qdmp` 命令
3. 在 CLI 提供的扫码登录、手动登录 URL、账号密码登录三种方式中任选一种
4. 登录完成后 CLI 会自动继续原命令；也可以执行 `qdmp-cli getMe` 验证

Agent 对话使用 `qdmp-cli login --agent --env prod`（开发环境为 `dev`），Agent 会展示浏览器登录链接和二维码图片，保持进程直到登录完成。详细流程见 [Agent 对话登录](../knowledge/agent-login.md)。无人值守的 CI 请设置 `QDMP_TOKEN`。不要在聊天中发送账号或密码。

## 五、命令参考

| 命令                              | 说明                                                                          |
| --------------------------------- | ----------------------------------------------------------------------------- |
| `qdmp-cli list`                   | 查看可用模板                                                                  |
| `qdmp-cli create <项目名>` / `qdmp-cli create <项目名> -t default` | 创建全栈项目，检查实际生成结果 |
| `qdmp-cli backend init --runtime go --json` | 为已迁移的新结构纯前端添加官方 Go 后端；已有后端时拒绝覆盖 |
| `qdmp-cli backend package --json` | 独立构建与打包检查 |
| `qdmp-cli backend upload --archive <zip> --sha256 <摘要> --version <版本> --json` | 同字节上传 temp-diff / 正式版本 |
| `qdmp-cli backend deploy --description "<说明>" --json` | 构建并发布后端，Agent 继续完成上线验收 |
| `qdmp-cli backend deploy --review --description "<说明>" --json` | 可选：构建后仅返回脱敏 diff 和继续参数，不发布；完整流程见 backend-production.md |
| `qdmp-cli config init --json` | 低层配置初始化；旧项目仍须完成目录、公开配置和 EMP 前端迁移，后端 readiness 单独报告 |
| `qdmp-cli config migrate --check --json` | 旧项目只读盘点：按根 qdmp.json 与 backend/ 目录分类，输出目录/配置迁移计划与阻塞项 |
| `qdmp-cli config migrate --json` | 迁移旧项目前端目录和公开配置；frontend_migration_required 阻止前端操作，backendReadiness 单独报告后端状态 |
| `qdmp-cli config sync --json` | 可选：更新本地公开兼容文件；日常命令直接读取主配置，无需先执行 |
| `qdmp-cli init -a <id>`           | 初始化空目标身份；已配置时拒绝覆盖，保留 MongoDB                                                                    |
| `pnpm install`                    | 安装依赖                                                                      |
| `pnpm run dev`                    | 开发模式                                                                      |
| `pnpm run build`                  | 打包构建（本地调试）                                                          |
| `qdmp-cli build`                      | 打包构建（发布上传前必须使用）                                                |
| `qdmp-cli getMe`                      | 查询 CLI 登录态 |
| `qdmp-cli login`                      | 主动打开三选一登录流程；扫码或 URL 登录成功后自动轮询并保存 Token |
| `qdmp-cli login --agent --env prod`   | Agent 登录：输出链接与 PNG 路径的 JSON 事件，等待浏览器回调或 App 扫码成功 |
| `qdmp-cli upload -d "<版本描述>"` | 上传部署；skill 自动总结当前版本变化并传入描述                                |
| `qdmp-cli upload --experience -d "<版本描述>"` | CLI ≥0.1.32；上传后自动设置本次版本为体验版并输出二维码，无需手填版本号 |
| `qdmp-cli experience --version <实际版本号>` | CLI ≥0.1.32；将已上传的开发版本设为体验版，不重新构建上传 |
| `qdmp-cli review --version <前端版本号> --auto-publish --json` | 当前 CLI 支持时提审并选择审核通过后平台自动发布；提审成功不代表已上线 |
| `qdmp-cli debug` | CLI ≥0.1.32；构建后启动 EMP 真机扫码调试，持续输出日志 |
| `qdmp-cli debug --no-build --json` | 使用已有 EMP 产物，输出二维码和设备日志的 NDJSON 事件 |
