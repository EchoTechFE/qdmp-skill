# 千岛小程序 Skill 使用指南

## 概述

千岛小程序 Skill 是一个帮助开发者快速创建、开发和部署千岛小程序的 Claude Code 技能。它提供了完整的开发流程支持，从环境配置到最终部署发布。

## 前置条件

1. 注册 [千岛开放平台](https://open.qiandao.com) 账号，创建小程序获取 `appId` 和 `appSecret`
2. 安装 [Node.js](https://nodejs.org)，qdmp-cli 支持 `^22.12.0 || ^24.11.0 || >=26.0.0`
3. 安装 Claude Code

---

## 一、环境配置

### 1. 安装开发工具

```bash
# 安装 pnpm
npm install -g pnpm

# 安装 qdmp-cli
npm install -g qdmp-cli

# 验证安装
qdmp-cli --version
pnpm --version
```

### 2. 添加 MCP 服务

```bash
claude mcp add --transport http qdmp-gitlab https://openapi.qiandao.com/gitlab/mcp
claude mcp add --transport http qdmp-aliyun https://openapi.qiandao.com/aliyun/mcp
```

### 3. 安装 Skill

```bash
# 添加插件市场
/plugin marketplace add https://github.com/EchoTechFE/qdmp-skill.git

# 安装插件
/plugin install qdmp-skill
```

## 二、快速开始

启动 Claude Code 后，使用 `/qdmp-skill` 触发千岛小程序开发助手。

### 创建项目

```
创建一个千岛小程序项目，项目名叫 myShop
```

新创建直接执行 `qdmp create myShop`，或保留显式 `-t default`。CLI 从 `git@github.com:EchoTechFE/qdmp-taro-template.git` 单次获取完整全栈模板，校验 frontend/backend 及自带的空 qdmp-config.json，保留主配置内容，只设置 0600 权限和忽略规则；不增加后端选项、不搬目录或拼装第二个模板。克隆流程移除模板 .git，因此生成项目中的主配置未被跟踪。官方模板仓库只提交 AppID、AppSecret、MongoDB 字段为空、variables 为 {} 的配置，不提交实际凭据；直接 git clone 也已有主配置，无需 config init。历史纯前端仍兼容；需要升级时 `qdmp backend init --runtime go` 从同一仓库临时提取后端，仅在主配置缺失时生成并继承旧字段，保留原源码位置及已有配置。规则见 [稳定后端模板](../knowledge/backend-production.md)。

上游全栈布局必须先合并，再发布对应 CLI。当前模板改动在研发分支准备审查，不能声称主分支已支持；旧 HEAD 布局不符时应停止，不临时拼装。

项目结构：

```
myShop/
├── frontend/
│   ├── src/
│   │   ├── pages/        # 页面
│   │   ├── components/   # 组件
│   │   ├── composables/  # 组合式函数
│   │   └── utils/        # 工具函数
│   ├── package.json
│   └── qdmp.json         # 小程序配置（appId、loader 等非敏感配置）
├── backend/              # CLI 稳定 Go 生产模板，监听 :8080
└── qdmp-config.json      # 权威主配置（身份、runtime、MongoDB、后端variables；敏感，需忽略提交）
```

日常命令直接优先使用主配置中的公开字段，不要求先 config sync；build 内部更新 Taro/EMP 需要的 qdmp.json，sync 只是可选本地工具。主配置坏或所选环境身份缺失不能回退旧前端身份；已有编译产物身份不属于主配置对应环境的有效身份映射时重新 build，不能只改 ZIP。没有主配置的旧纯前端保持原流程。秘密和后端 variables 不导入前端；MongoDB 省略/null/双空时无持久化，部分填写错误，后端配置变化需重新打包。规则见 [配置优先级](../knowledge/backend-production.md#配置优先级与前端兼容)。

### 开发调试

**全量调试（推荐）**：

```
部署测试环境
```

Claude 会按实际项目范围启动服务；全栈先验证本地后端，再启动前端 dev server，不自动改写前端地址。默认模板从公开 AppID 推导正式后端域名，登录示例仍需已部署的正式后端；已有项目按其实际本地代理配置联调。原生 `pnpm dev` 前，存在主配置时先在根目录执行 `qdmp config sync --json` 导出公开字段，再进入实际前端目录。

```
本地测试环境已就绪

  前端 dev server: http://localhost:10086
  后端 API:        http://localhost:8080
```

**单独调试**：

```
部署后端测试环境    # 仅启动后端
部署前端测试环境    # 仅启动前端 dev server
```

**真机调试**：

```bash
qdmp build
qdmp-cli upload -d "真机调试版本"
# 使用千岛 App 扫码预览
```

### 发布上线

Agent 先根据真实代码/入口识别形态：纯前端只执行前端步骤，无需 AppSecret、Go 或后端主配置；全栈先后端再前端；纯后端只运行后端工具，不发布前端。有真实后端实现但配置不完整时报告待配置项，不能降级为纯前端。

```
部署上线
```

以下工具链仅针对全栈范围：Agent 先用 `qdmp backend package --json` 生成并验证私有生产包，再执行 `qdmp backend deploy --archive <zip> --sha256 <摘要> --version <vX.Y.Z> --description "<说明>" --json` 获取 diff / reviewDigest，审查后追加 `--review-digest`，通过 [后端 MCP](../references/backend-mcp.md) 自动发布并跟踪正式 master 合并。命令只返回 Pipeline 事实和 acceptance_required，不自动查询 Aliyun/K8s；Agent 通过宿主 MCP 查询实际版本、Job/副本及日志，并验证健康接口。build/deploy、两个新副本 Ready、运行版本与 `/healthz`、`/readyz` 全部通过后，核对前端使用的 `https://{appId}.qiandaomp.com` 并继续上传；默认模板由公开 AppID 推导地址，只有旧项目存在实际地址配置时才按其契约修改。Pipeline success 或镜像 tag 单独不足。已授权的正式发布连续执行；初始化、分析、打包不会自动上线。生产流程不依赖浏览器。

前端 `upload` 成功只表示上传版本。正式上线还需将真实版本设为体验版并提审；当前 CLI 支持 `qdmp review --version <实际版本号> --auto-publish --json`，由平台在审核通过后自动发布。提审成功不代表已上线，最终状态以平台结果为准。发布规则、diff 审查和验收由 Skill 维护，Agent 编排；CLI 执行，MCP/API 服务由平台提供。

## 四、常见问题

### qdmp-cli 命令未找到

```bash
npm install -g qdmp-cli
```

如果仍然找不到，检查 npm 全局路径是否在 PATH 中：
```bash
npm config get prefix
# 确保 {prefix}/bin 在 PATH 中
```

### 依赖安装失败

先运行 `node --version`，核对[前置条件](#前置条件)中的 CLI 运行时范围。Node 20 不再受支持；保留旧纯前端项目源码，不代表旧 Node 仍可运行新版 CLI。运行时不兼容时使用已选择的受支持 Node 环境，不自动更换用户全局 Node，也不通过跳过安装脚本或编译检查绕过错误。

确认网络正常，可尝试：
```bash
pnpm install --registry https://registry.npmmirror.com
```

### 登录失败

1. 检查网络连接
2. 在支持输入的前台交互终端中执行目标 `qdmp` 命令
3. 在 CLI 提供的扫码登录、手动登录 URL、账号密码登录三种方式中任选一种
4. 登录完成后 CLI 会自动继续原命令；也可以执行 `qdmp getMe` 验证

Agent 对话使用 `qdmp login --agent --env prod`（开发环境为 `dev`），Agent 会展示浏览器登录链接和二维码图片，保持进程直到登录完成。详细流程见 [Agent 对话登录](../knowledge/agent-login.md)。无人值守的 CI 请设置 `QDMP_TOKEN`。不要在聊天中发送账号或密码。
