# 运行数据收集推荐与授权指引

QDMP 只负责推荐、告知和调用指引；安装、授权、宿主适配、采集、上报与撤回由 Agent Runtime Telemetry 实现。收集选择或失败不阻塞原有开发、登录、部署流程。

## 首次推荐与共同边界

首次加入按 [SKILL.md 的收集入口](../SKILL.md#启动先查收集状态)展示单题选择和原详细说明链接。

- 入口不可用或安装失败时说明已核实状态、原因及下一步。未经检查不写“未安装”“未授权”；“本次未激活”不等于已有收集已停止。
- 当前目录已有有效授权或明确拒绝证据时不重复询问；其他目录授权、全局已安装或缺少 MCP 工具都不能代替目录状态。
- 只有完整告知后的实际选项提交或明确文字回复才是授权。默认高亮、工具成功、`status=ok`、历史同意、Agent 自述和无上下文的“同意”均不是新授权。沉默、取消、暂不决定或要求继续业务时不激活、不当作拒绝，继续业务。
- 发布说明链接、日期占位符或“草案”仅如实提示待完善，不额外增加安装门槛；不擅改法律原文。清单、关键数据说明、版本或哈希校验不通过时仍须暂停收集操作。
- 宿主执行许可独立生效。已同意当前目录和同一上报范围时直接沿原流程续办，无需重述授权长句。宿主另需确认时，由用户在宿主原生审批界面操作。明确安全拒绝后停止该动作，不重试绕过。

## 唯一入口与数据说明

首次安装和目录激活优先使用 [monitor-flow 脚本状态机](./monitor-flow.md)。本文保留授权说明与 telemetry 协议细节；状态机强制校验从告知到授权、校验、检查及执行的顺序，不依赖 Agent 自行记住参数。开启动作不直接手工调用 onboarding enable。

**无 MCP 的冷启动是受支持路径，不能直接报告入口不可用。** 安装之前没有 telemetry MCP、本地没有收集文件均属正常；不要扫描业务目录寻找入口。按实际 Skill 安装路径读取下述唯一清单。

读取同目录的 [telemetry-distribution.json](./telemetry-distribution.json)，即实际 Skill 安装目录下的 `references/telemetry-distribution.json`。不读取用户工作目录或仓库根副本，也不扫描其他目录寻找替代清单。

- `onboarding` 指定 telemetry 发布的独立 Node.js 入口、版本、HTTPS URL 和 SHA-256；`pre_download_notice` 是绑定该发布版本和两个制品哈希的完整告知与法律原文。
- 已有 telemetry MCP 时，可用 `project_status` 只读检查目录状态；已有获准且校验过的本地 onboarding 时，可调用 `status` / `notice`。没有本地入口的冷启动必须先本地告知、取得明确确认，不能为查询状态或能力提前下载执行代码。
- `onboarding` 为 null、入口缺失、校验失败，或 `pre_download_notice` 缺失/不完整、版本或哈希不匹配时，说明“收集引导尚不可用”及原因。不联网补文案绕过确认，不退回旧 Bootstrap。

## 目录范围：普通模式与精确模式

确认真实宿主（Codex、Claude Code、Qoder）和实际绝对工作目录，不猜测。入口返回的项目根目录不同时，并列展示传入目录、返回目录及只读核实的识别依据。正常项目子目录不一定是错误；已有效授权且覆盖当前目录的范围可沿用，但不得自动扩大用户限定的范围。

用户仅授权指定目录时，按能力而非写死版本号处理：

1. 对已获准且校验过的入口查看 `help`；支持 `--exact-workspace` 才使用精确模式，不向不支持的旧入口强塞参数。
2. 精确模式下，后续每次 `status`、`notice` 都传相同的用户授权绝对目录、宿主和 `--exact-workspace`；包括下载后的首次查询、失败复查和重新生成选项。
3. 执行包含目录授权的动作前，核对返回的 `project_root` 与授权目录一致，且所选 `choices[].argv` 保留该目录及 `--exact-workspace`。不自行拼接遗漏的参数；不一致则暂停排查。运行时能力由中央入口检查 `activation-capabilities.exact_workspace`。
4. 入口或运行时不支持时暂停激活，说明需兼容更新并明确授权；不能移除参数退回父目录，不能创建 `.git`、修改项目配置或伪造回执来改变识别结果。

用户愿意接受识别出的父项目范围时，须先展示该实际范围及完整说明，取得对应授权；范围确认本身不能替代数据采集授权。

## 开启或更新：一次明确授权

1. **本地完整告知**：仅展示 `disclosure.display`，完整说明通过其中的链接打开，不摘要、不拼接 `consent_template` 或独立元数据清单。`consent_template`、目录、宿主、固定版本、制品 URL/SHA-256 和上报目标仍由状态机绑定及校验，不作为第二份用户文案。
2. **一次决定**：在法律文案展示后只取得一次明确选择。冷启动范围以固定清单 permitted_action 及已展示文案为准：旧清单仅包含固定版本条件式安装/同版本复用；新清单 install_if_missing_or_reuse_compatible_version 明确告知后可复用宿主已确认的其他兼容版本，不另问一次版本动作。两者均不包含自动更新或降级。中央入口随后返回的动作在这个范围内时直接继续，不再询问；超出范围时才重新告知。选择「暂不开启」时，先保存本地决定，再执行下述拒绝行为上报。
3. **下载、校验、复核**：授权后下载到独立临时位置，校验固定 SHA-256，再依本次目录模式分别调用 `status` 和 `notice`。下载校验与执行分开，不用 curl 管道执行；URL 不能带 Markdown 包装。核对目录、版本、权限、上报目标及完整文案与此前告知一致；法律原文须与清单相同，动态告知仅允许已声明的目录/选项等替换。
4. **执行已同意动作**：冷启动条件式同意允许 `install` 或清单已告知范围内的兼容 `reuse`；分别核对安装/目录收集/上报或仅目录收集/上报权限。已授权不重复激活；没有可执行项则按状态处理，不虚构授权选项。范围、版本或动作超出已告知内容时才重新告知确认。条件一致则原样使用所选 `choices[].argv`，不再次询问同一业务授权，不改写版本约束。入口未内嵌制品地址时仅按其协议使用清单的 `--artifact-url`，不回退私有仓库。
5. **按实际运行时处理登录及宿主要求**：新运行时采集不要求登录或 appId，不为收集主动扫码；people-v1 仅在已告知且固定清单声明时允许账号摘要查询，旧授权不自动扩展。旧运行时若明确要求 QDMP_LOGIN_REQUIRED，复用 [Agent 对话登录](../knowledge/agent-login.md)，完成后按 monitor-flow 的 resume 恢复同一目录和版本授权；不重新告知采集、不重装。必要的宿主信任或重启仍按实际宿主证据处理，先核对聊天绑定工作区、再补齐缺失 Hook，不根据缺少事件推断未信任或强制重启。

## 拒绝行为上报

首次安装引导展示 `disclosure.display` 的简短收集说明、详细说明链接和单题选择。事件字段、接口、协议版本和工具参数仅供 Agent 查阅，以分发清单的 `pre_download_notice` 和下述入口为准。明确点击或文字回复「暂不开启」时，先用 `authorize --decision decline` 保存本地终态。只有用户作答前已实际看到适用的拒绝上报告知，且未要求不上报，才能调用以下入口一次。链接说明页中的告知可用于此判断，例如用户在同一条拒绝回复中明确说明已阅读该节。只展示链接、Agent 自己读取告知或收到无法确认已看到告知的普通点击时，只保存本地决定。无需为核实阅读另行提问。处理完成后直接继续原任务。正式使用时省略拒绝确认、进度提示、回执、事件编号和上报结果。回执留在工具记录中，用户主动要求核对时再说明。

- 优先使用现有的 `report_monitoring_declined`，传入该流程的实际 `cwd`、`host`、`declined: true`、`notice_version: "monitor-install-decision-v1"` 和 `notice_shown_before_decision: true`。只有实际提前展示告知时才传该标记。
- 工具不可用时使用同一固定发布清单的 onboarding 入口。没有已校验的本地副本时，在已告知并获准执行的范围内下载固定入口并校验 SHA-256，然后只运行 `decline --cwd <实际绝对目录> --host <实际宿主> --declined --notice-shown-before-decision --notice-version monitor-install-decision-v1`。该路径不安装插件、不登录、不启动持续收集。下载或执行受宿主拦截时结束引导。
- 用户明确要求不上报、跳过、取消、沉默、未提前展示告知，或拒绝的是更新或已有安装下新增目录采集时，不发送拒绝事件。历史拒绝不补报。发送失败保留本地拒绝状态并继续业务，不启动后台重试。

## 命令职责与用户控制

所有 CLI 调用均使用 `node <已校验且获准的 onboarding 绝对路径>`，但参数来源不同：

- `status` / `notice`：使用本次目录模式的查询参数，不读取授权动作的 argv。
- 安装、开启或更新：使用用户所选 `choices[].argv`；不自行实现安装。
- 查看采集状态：telemetry `project_status` 或 onboarding `status`，不以全局安装状态冒充目录授权。
- 关闭采集：交给 telemetry MCP `revoke_consent`，如实报告撤回或待完成状态；工具不可用时说明未完成，不以拒绝安装、删配置或退出会话冒充撤回。
- 重新开启：重新走当前范围的完整告知与授权，不把撤回前的历史同意复用为新授权。
- 删除已上传数据：说明需联系 `openqiandao@echo.tech` 申请，不承诺已删除、不自动代发邮件。

运行说明与法律文案由 telemetry 公开包内 `docs/runtime-guide.md` 和 `docs/legal/` 维护，不访问内部仓库。区分后台激活、真实 Hook 观察和日志库回查：`hooks_pending` 不等于已采集，HTTP 成功不等于落库成功；原生 Hook 未验证时不承诺每条消息均采集，不扫描历史会话补采。
