# EMP 页面与组件优化

新建或改动列表、图片密集页、多页流程和弹层时，在设计阶段明确首屏要完成的操作、首屏所需数据和组件、后续加载的触发点，以及旧宿主的可用路径。已有项目按本次业务问题和源码中的明确风险确定改动，沿用已验证的页面栈、请求封装和接口契约。

## 组件选型

1. 从当前项目的 `frontend/README.md`、`package.json`、锁文件、`DESIGN.md` 和现有页面查找组件。优先选用千岛提供且已确认支持目标 EMP 的组件或原生能力，其次复用工程内同用途且已验收的组件。核对实际包名、导入方式、版本、属性、事件、当前宿主支持范围和实际样式。第三方文档或已有 H5 示例只提供候选。
2. 没有可用的千岛专用组件时，用官方模板的 Taro 小程序基础组件（如 `view`、`text`、`image`、`scroll-view`）配合已确认的 QD Bridge 和项目设计系统。没有证据时不猜 npm 包名、组件名或属性。EchoTechFE 的 `dangoui` README 标明面向 Web 和 UniApp，接入 EMP 需要额外的兼容证据。 [千岛技术架构](https://open.qiandao.com/docs/guide.md) · [官方 Taro 模板](https://github.com/EchoTechFE/qdmp-taro-template) · [dangoui](https://github.com/EchoTechFE/dangoui)
3. 新能力在项目锁定的 Taro、插件和编译器版本下构建，用最小真实页面核对渲染、交互、滚动和宿主返回行为。组件或属性不支持时，使用已验证的基础组合或保留现有路径。对于有正式能力探测的 Bridge，调用前使用 `qd.canIUse` 或该方法文档指定的检测方式。Taro 对其他平台的支持表和 EMP 编译成功都不能证明目标千岛宿主的行为。 [千岛 Bridge](https://open.qiandao.com/docs/bridge.md)

## 列表与分页

- 列表数据会增长时，首屏只取一页和卡片实际需要的摘要字段，详情按用户选择请求。小且有明确上限的静态选项可一次读取。明确筛选与排序的默认值、页大小、结束条件、首次加载 / 空态 / 首屏错误，以及后续页失败时如何就地重试。
- 按接口正式契约维护游标或偏移。服务端返回 `hasMore` 或下一页标识时据此继续；仅有偏移时，按该接口定义推进和结束。不要通用地从短页、总数或当前列表长度推断末页；例如有些千岛接口的总数会封顶。若游标重复或无法前进，停止自动加载并保留当前结果。 [心愿单分页实例](../../qdmp-skill/knowledge/wishlist.md#分页与错误)
- 整页滚动使用项目已验收的页面触底方案，局部滚动可用已验收的 `scroll-view` 触底事件，每个列表只选一个触发源。相同查询参数和页标识的在途请求合并，按稳定 ID 去重，成功后才推进页标识，失败重试当前页。新搜索、排序、刷新时重置页标识并标记请求代次，只应用当前代次结果；支持取消则取消旧读请求。切换账号或权限时隔离或清空私有状态和缓存。宿主触底能力未确认时保留「加载更多」入口。 [Taro ScrollView](https://docs.taro.zone/en/docs/components/viewContainer/scroll-view/)
- 避免在滚动高频回调里请求或整表重算。先用有限分页和轻量卡片。累计多页后仍有卡顿或内存问题，再评估 EMP 验证过的窗口化列表，保留返回列表时的滚动位置。只有新旧请求体、响应和默认行为明确兼容时才迁移现有前端。 [业务 API 的分页规则](../../qdmp-skill/knowledge/api-optimization.md#通用规则)

## 首屏、懒加载和预加载

| 对象 | 先采用的方案 | 兼容处理 |
| --- | --- | --- |
| 页面与数据 | 启动入口先显示可操作的页面和首屏必要数据，将详情、非首选 Tab 与低频页面的请求放到实际进入时。复用本轮仍有效的结果，避免每次页面显示都刷新。 | 保留已有页面路径、对外跳转参数和返回行为。已有缓存或路由能满足时从数据加载优化开始。 |
| 组件与资源 | 需要时才挂载复杂面板和弹层，关闭或卸载时释放监听、计时器和媒体等资源。只是隐藏的组件仍占内存，条件挂载也不意味着代码被拆包。图片优先使用尺寸匹配的缩略图、固定占位和明确的错误回退，首屏图优先。 | 在目标宿主核对图片懒加载属性的实际效果。不支持时依靠有限分页、缩略图或已验证的按可见区域渲染。 [Taro Image](https://docs.taro.zone/docs/components/media/image) |
| 代码分包与预下载 | 仅在业务需要分离低频页面或已有明确包体问题时评估分包。必须同时确认项目编译链产物确实拆出相应代码，目标宿主在冷启动、直接进入和返回时成功装载。 | `subPackages`、`preloadRule`、`lazyCodeLoading`、动态 `import()` 的 Taro 或微信行为不能直接套入 EMP。缺少版本或真机证据时保留已验证的静态加载，先做组件延迟挂载与数据按需请求。 [Taro 全局配置](https://docs.taro.zone/docs/app-config) |
| 数据预取 | 首屏完成后，有明确的下一步且适合复用结果时，预取一份最可能使用的只读数据，例如快到列表底部时的下一页。优先单路并发，设置请求额度和短有效期，同一键复用在途结果。 | 请求用原有授权、用户、环境和查询上下文，切号和切筛选时丢弃失效结果。不给预取发送表单、触发授权、预取一整页所有详情或自动无限重试。弱网、限流、不可取消或用户行为不确定时按需加载。读取多个外部数据源时遵守各自限额；全量验收另走 [云服务使用规范](../../qdmp-skill/knowledge/backend-operations.md#云服务使用规范)。 |

## 弹层还是独立页面

| 任务 | 选型与验收 |
| --- | --- |
| 短确认、取消、少量选项 | 优先使用目标宿主已验证的 `qd.showModal`、`qd.showActionSheet` 或项目已有的可用封装。由用户操作触发，以实际选择结果决定后续动作，取消自然回到当前页面。阻止重复打开和重复提交。底层不支持时用同一位置的兼容确认组件，仍需明确确认才执行。 [千岛 Bridge](https://open.qiandao.com/docs/bridge.md) |
| 与当前内容紧密相关的短表单、少量筛选 | 使用已确认支持 EMP 的千岛组件或项目内已有的弹层。打开时再挂载和取数，核对安全区、键盘遮挡、背景滚动、遮罩及系统返回键。提交中与失败时显示明确状态，保留未提交输入。 |
| 多步骤、需要滚动的大表单、独立详情或须直接跳转的内容 | 使用独立页面，按既有页面栈和跳转参数加载。返回时保留列表筛选与滚动位置，未提交数据按产品约定处理。 |

禁止用通用业务弹层仿造宿主授权或绕过系统权限。普通业务失败可在对应区域显示并重试，避免同一故障反复弹窗。

## 真机回归与验收

1. 用 `qdmp-cli build` 生成 EMP 包并用千岛 App 打开。记录构建标识、宿主 App 和 SDK 版本、设备及网络。按改动核对首屏可用、后续页加载、详情或弹层打开和长列表滚动。涉及分包时检查实际产物与冷启动、直达页面和返回路径。
2. 按改动测试刷新、切筛选、弱网后重试、末页、快速开关弹层、按系统返回键和切号。对旧宿主实测新增能力缺失时的备用入口。记录页面和构建证据，未能真机覆盖的端或版本写明待验。
3. 检查首屏只发必要请求，后续加载能继续、失败可重试，且没有重复请求、错误页标识或状态闪回。常规交付无需性能基线或基准测试。遵循 [真机调试](../../qdmp-skill/knowledge/development-guide.md#真机调试)，HTML 设计稿和 H5 预览只能提供视觉对照。
