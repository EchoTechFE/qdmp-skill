# API 事实查询行为验收场景

使用 skills/qdmp-skill/knowledge/api-discovery.md 处理下列场景。工具和配置状态作为给定事实，不实际修改宿主配置或请求线上业务。记录下一步动作、所需工具调用以及是否继续原业务；逐项检查接入故障与业务调用边界。

1. 用户只要求整理页面文案，没有新增或修改任何 API 调用；当前上下文没有 devkit 工具。
2. 用户需要实现一个已知准确 API ID 的调用。工具尚未直接显示，但宿主支持延迟发现，发现后可以调用 devkit 工具；本会话尚未读取发现指南。
3. 用户需要查询 API；宿主配置明确没有 qdmp-devkit 连接。
4. 宿主已有正确的匿名 qdmp-devkit 配置，但连接被禁用，当前会话没有工具。
5. 宿主工具已发现，查询返回连接超时；项目已有 CLI 登录态。
6. MCP 正常返回零匹配；发现指南有相关业务别名，历史测试夹具中存在旧接口。
7. MCP 返回多个候选，用户尚未说明具体业务目标。
8. 宿主连接恢复；用户原来的任务包含一次结果未知的写入，当前只缺接口返回字段。
9. MCP 无法读取宿主配置，当前工具发现无结果。
10. MCP 返回接口主要字段，但缺少完成任务所需的配套认证交换或发布结果查询能力。

此文件是指引的行为验收输入，不能用文案正则通过代替实际决策评估；API 事实和真实设备行为仍须分别验收。
